# Developer walkthrough

A guided tour of the repository: how the pipeline is structured, what each stage
does, and how to run, reproduce, or extend it. For the science (data choices,
method, results, limitations) see [ANALYSIS.md](ANALYSIS.md).

## How it fits together

The pipeline is four stages, joined on the `year` column. Each stage has a module
in `src/` and a matching notebook in `notebooks/`; the notebooks import the
modules and add narrative and plots.

```
ISTAT production ┐
                 ├─ join by year ─ classify each year ─ dashboard
climate indices  ┘
```

Everything configurable (paths, region, thresholds, sampling points, window)
lives in `config.py`. To retarget the analysis you edit that file; you do not edit
the stage modules.

## Running it

Recommended: open `notebooks/` and run `01` to `04` in order. Each notebook first
runs a bootstrap cell that locates the project root, so it works from the
`notebooks/` folder without any path setup.

Equivalently, from the project root:

```bash
python -m src.production
python -m src.climate_ingest_openmeteo
python -m src.compound
streamlit run app.py
```

## The stages

### 1. Production (`src/production.py`, notebook 01)
Loads the ISTAT wine-grape extract and corrects a **mislabelled header** (the
column headings are shifted one place, so `Observation` actually holds production,
`Amount` holds area, and so on). Builds two outputs:

- `piedmont_production.csv`, the regional annual total (sum of the 7 provinces).
- `piedmont_production_by_province.csv`, the per-province breakdown that feeds the
  dashboard choropleth; it keeps the NUTS-3 code so it joins to the GeoJSON.

Yield is recomputed from regional totals (production / area), not averaged from
per-province ratios.

### 2. Climate (`src/climate_ingest_openmeteo.py` + `src/climate_indices.py`, notebook 02)
`climate_ingest_openmeteo` fetches daily maximum temperature and precipitation
for the wine-district sampling points (`config.WINE_DISTRICTS`) from Open-Meteo,
averages them into a regional daily series, and calls `climate_indices` to reduce
each year to a set of indicators (`piedmont_climate_indices.csv`):

- `summer_heatwave_days`: JJA days above `HEAT_TMAX_THRESHOLD_C`
- `summer_mean_tmax_c`: mean JJA daily-max temperature
- `growing_precip_mm`: Apr-to-Sep total precipitation
- per-month temperature and precipitation, used to tell concurrent from sequential

Two data-quality points are handled in the ingest: the pure ERA5 model is
requested explicitly (the default model has whole-year gaps over Piedmont), and
the ERA5 precipitation gap in 2017 is back-filled from the best_match model. Each
district response is cached under `data/raw/openmeteo/`, so re-runs are instant.

`src/climate_ingest.py` is the alternative Copernicus CDS path, kept for
cross-checking (see README for setup). It produces NetCDF files that
`climate_indices.main` reads.

### 3. Compound classification (`src/compound.py`, notebook 03)
Joins detrended production to the classified climate and labels each year
`normal`, `heat_only`, `drought_only`, `concurrent`, or `sequential`. Severity is
defined at the year level (the hottest / driest `COMPOUND_SEVERITY_PCTL` fraction
of years); month-level timing then separates concurrent (overlapping) from
sequential (different months). `headline()` returns the compound-vs-normal yield
comparison used by the dashboard. Output: `piedmont_compound_analysis.csv`.

### 4. Dashboard (`app.py`, notebook 04)
A Streamlit app: an animated province choropleth (production or yield, by year),
the compound comparison and finding, a yield timeline coloured by category, and a
per-year event ribbon. It reads the processed CSVs and the province GeoJSON, and
falls back to a production-only view if the compound analysis is absent. The theme
is in `.streamlit/config.toml`. Streamlit runs as its own server, so notebook 04
launches `app.py` rather than embedding it.

## Reproducibility

- The notebooks are generated from `build_notebooks.py`; edit that script and
  re-run it rather than editing the notebooks by hand.
- Raw climate files and the Open-Meteo cache are git-ignored and regenerated by
  the ingest scripts. The processed CSVs are small and reproducible from a clean
  checkout by running stages 1 to 3.

## Extending it

- **Longer window:** set `CLIMATE_START_YEAR` earlier in `config.py`. The climate
  sources reach 1940. Note the production-climate comparison is bounded by the
  production record (2006 onward); a longer window is useful for a climate-only
  stress trend.
- **More regions:** add the region's ISTAT rows and its province polygons, then
  point the province codes and sampling points in `config.py` at the new region.
  No stage code needs to change.
- **Different thresholds:** `HEAT_TMAX_THRESHOLD_C`, the season windows, and
  `COMPOUND_SEVERITY_PCTL` are all in `config.py`. The last one is the largest
  lever on the result; ANALYSIS.md shows its sensitivity.
